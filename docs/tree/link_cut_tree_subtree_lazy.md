### データ構造の概要

動的木（根付き木であることを保ちながら辺の追加・削除）を管理する。
各頂点 $v$ は、型 `S` のデータ $A_v$ を持っている。
型 `S` のデータは、`op` 等の演算によって集約され、その結果もまた型 `S` で表される。
セグメント木のよくある設計と同じである。

link-cut tree の各ノードは、森の各頂点に一対一で対応する。
ノードの情報は、$1$ つの `LCNode` インスタンスで管理される。
頂点 $v$ に対応する `LCNode` では、以下の情報が管理される。

* `LCNode *c[2]` : link-cut tree における子。$0$ 番が元の木における根側、$1$ 番が子孫側。
* `LCNode *p` : link-cut tree における親。
* `S a` : $A_v$。
* `S sum` : link-cut tree における $v$ の部分木にわたって集約されたデータ。
* `S sum_r` : link-cut tree において $v$ に rake された部分にわたって集約されたデータ。

型 `S` のデータに対して、型 `F` のデータを作用させることができる。
遅延セグメント木と同様である。

### インターフェース

* `v -> apply (f)` ( `F f` )
    link-cut tree 全体のデータに $f$ を作用する。
* `v -> expose ()`
    以下の条件を満たすように、link-cut tree を変形する。
    * `this` が link-cut tree における根である。
    * 元の木における根から $v$ までのパスが main path である。
* `v -> evert ()`
    元の木における根を $v$ に変更する。
    伴って、`this` が link-cut tree における根になる。
* `v -> link(r)` ( `LCNode* r` )
    辺 $(r,v)$ を追加する。
    伴って、操作対象の link-cut tree の根および元の木における根が変化する。（変化先は規定されない）
* `v -> cut()`
    $v$ と $v$ の親を結ぶ辺を削除する。
    伴って、操作対象の link-cut tree の根および元の木における根が変化する。（変化先は規定されない）


### 使用上の注意

特殊例として、パス型の木のみを扱うことで、列に対するデータ構造として使ってもよい。
その場合は、`evert` や `expose` の代わりに `splay` を使うことで、子孫側が切り離されないようにする。
